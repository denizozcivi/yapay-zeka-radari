A $200 Windows botnet sells AI credit draining as DDoS.
If that method runs against one of your keys, the first signal is the provider's invoice.

Qrator Labs documented x47.c, a Windows botnet sold by WraithTools. An August ad put the base package at $200 and the full one at $950. The panel's DDoS tab carries 18 attack methods, from HTTP floods and a TLS stresser to one listed as AI API draining. The stealer side collects browser passwords, cookies, Discord tokens, wallet data and AI-site tokens.

The drain takes two inputs, a model name and a valid API key for the target account on OpenAI, xAI or a compatible chat API, and the bots send billable requests with it. Those requests go straight to the provider, so they never pass through the victim's application. Your gateway and rate limits are not in the path, and your request logs stay flat while the usage counter climbs. The same panel runs an AI Stealth module that asks Grok to pick persistence actions from a predefined set, startup entries and scheduled tasks, and reports status back, including Windows Defender exclusions.

The stealer and the drain ship in one product. One tab collects AI-site tokens, another spends them. A key sitting in a .env file or a CI variable is a billing liability now, and few teams alert on it.

Do this today: take yesterday's request count from your OpenAI or xAI usage page and compare it with what your own application logged for the same hours. A gap is someone else's traffic on your key.

Which of your LLM keys has a hard spend cap on it right now?
